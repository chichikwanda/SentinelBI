# SentinelBI

AI-powered cybersecurity business intelligence for ICT SMEs in Zimbabwe: descriptive,
predictive and prescriptive analytics over network flow data. This is a final-year research
prototype. The engineering plan is `cyber-bi-project-plan.md`; design decisions and deviations
from it are in [docs/DECISIONS.md](docs/DECISIONS.md).

**Status: Phase 0 + thin vertical slice.** Register an organisation, register a source, send
flows (HTTP API, CSV replay or NetFlow), and watch alerts appear live. The classifier is a
**placeholder rule set, not a trained model**; real model training is Phase 2.

## Run it

Requires Docker with Compose v2. No other tooling is needed to run the stack.

```bash
cp .env.example .env          # `make up` does this for you
docker compose up -d --build --wait     # or: make up
```

| Service  | URL / port                         |
|----------|------------------------------------|
| Web UI   | http://127.0.0.1:3000              |
| API docs | http://127.0.0.1:8000/docs         |
| NetFlow  | UDP 2055 (collector)               |

With `SEED_DEMO_DATA=true` (the `.env.example` default, dev only) a demo organisation is
seeded:

| Login (password `dev-only-demo-password`)  | Role    |
|--------------------------------------------|---------|
| `admin@demo.sentinelbi.example`            | admin   |
| `analyst@demo.sentinelbi.example`          | analyst |
| `viewer@demo.sentinelbi.example`           | viewer  |

### Replay sample traffic

`data/samples/synthetic_flows.csv` is **synthetic** (705 flows: 600 benign, an 80-port SYN scan,
a UDP flood), generated by `ml/src/synth_sample.py`. It is for pipeline demos only, never for
training or evaluation. Replay it through the real ingest API with the demo source's key:

```bash
make replay
# equivalent:
docker compose run --rm migrate python -m app.services.ingestion.csv_replay \
  --file /repo/data/samples/synthetic_flows.csv --api-url http://api:8000 \
  --api-key sbi_demo_dev_only_api_key_0000000000000000
```

Sign in as the demo admin: within a few seconds the dashboard shows a **DoS/DDoS** (High) and a
**Recon/Scan** (Medium) alert, and the source flips to *Receiving*.

### Onboard your own network

`/sources/new` is the wizard. An IP address alone gives the platform no traffic, so the wizard
creates the source, shows a one-time API key and the collector address, and gives copy-paste
router config (MikroTik, pfSense, Cisco) or an HTTP/curl example. It then polls until the first
flows arrive. NetFlow exporters are only accepted from the registered address; unknown or
ambiguous exporters are dropped and logged ([ADR-005](docs/DECISIONS.md)).

## Test

```bash
make test        # pytest in the Linux dev image against a throwaway database (74 tests)
make lint        # ruff + ruff format --check + mypy (strict)
make e2e         # Playwright smoke test against the running stack
```

`make test` creates and migrates a scratch database `sentinelbi_test` on every run, so the
Alembic migration is exercised each time. The suite covers auth and roles, ingest, the worker
(idempotent redelivery, dead-lettering), tenant isolation, training/serving feature parity, the
collector, the migration (ORM/migration drift, hypertables, retention) and the seed.

Without `make` (e.g. Windows) run the underlying commands:

```bash
docker compose --profile test run --rm --build test pytest
uvx pre-commit run --all-files            # hooks run the locked ruff/mypy
cd tests/e2e && npm ci && E2E_BROWSER_CHANNEL=chrome npx playwright test
```

Host runs (`uv run --project backend pytest` from the repo root, with `docker compose up -d db redis`)
also work. Use `127.0.0.1`, not `localhost`, for published ports: on Windows `localhost`
resolves to `::1` first and every connection stalls for about two minutes.

## Layout

```
backend/    FastAPI API, Alembic migrations, worker, services (uv project)
collector/  UDP NetFlow v5/v9/IPFIX listener (own container)
ml/         shared feature module (sentinelbi_ml), Phase-2 training stubs
frontend/   Next.js 16 (App Router, TypeScript, Tailwind, TanStack Query)
tests/      pytest (backend, collector), Playwright (e2e)
data/       datasets (gitignored) + DATASETS.md ledger + synthetic sample
docs/       DECISIONS.md (ADRs)
```

Data path: `router/replay/sensor -> collector or POST /ingest/flows -> Redis Stream flows.raw ->
worker (features -> predictor -> persist -> alert) -> Postgres/TimescaleDB -> API -> web`.
Training and serving share one feature module, `ml/src/features.py`.

## Security and privacy defaults

- Every tenant table carries `org_id` and every query is scoped by it (tested).
- API keys are SHA-256 hashed and shown once; passwords use argon2id; JWTs are kept in an
  httpOnly cookie by the web app's server-side proxy, never in page JavaScript.
- No payload capture: the ingest schema rejects unknown fields. `PSEUDONYMIZE_IPS=true`
  replaces internal addresses with keyed per-organisation pseudonyms before storage.
- Flows and predictions are retained 30 days (Timescale retention policies).
- Active scanning is not implemented and the `scan` method is rejected until the
  ownership-attestation flow and audit log exist.
- `ENV=prod` refuses to start with the dev-only secrets or demo seeding enabled.

## Known gaps

See the end-of-session summary and [docs/DECISIONS.md](docs/DECISIONS.md). Notably: placeholder
classifier, unidirectional-vs-bidirectional flow mismatch, exporter identification, no SSE yet
(the UI polls every 3 s), and no real-router NetFlow test on this machine.
